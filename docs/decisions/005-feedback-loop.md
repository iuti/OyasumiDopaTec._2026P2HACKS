# 005: 人のフィードバックが返って直るまでを最短にする

- 日付：2026-11-25
- 決めた人：（PR のレビューで決める。提案はいうてぃー）

## 決めたこと

- PR ごとにスマホで開けるプレビュー URL を出し、`main` の最新版は固定 URL で Discord にピン留めする。
- プレビューはログインや準備なしで体験の中心に入れるようにする（デモ用データを最初から入れる）。
- PR とレビュー用ドキュメントの先頭に、プレビュー URL・試し方・見てほしいことを書く。PR テンプレートに「プレビュー」欄を足す。
- 感想はどこに書いてもらってもよく、AI が拾って Issue にする。小さな指摘はその日のうちに直して URL 付きで返す。
- 同じ指摘が2回出たら、テスト・自動チェック・AGENTS.md のルールで再発を防ぐ。
- 技術選定では、プレビューの出しやすさとビルドの速さを重く見る。

## 理由

- 実装は AI が速く進められるので、作品の質を決めるのは「人が触って、感想を返して、直る」を何周できるかになる。
- 前に Unity で作ったときは、試すまでの手間が大きく、触る回数が減った。開くまでの手間をなくせば、すき間時間でも触れる。
- 感想を Issue の形で書くのは人にとって重い。AI が拾えば、人は思ったことを書くだけで済む。

## 検討したほかの案

- 決まった日にまとめてレビューする：準備はいらないが、1周が長くなり、直す量が一度に増える。

## 影響（変わること・注意すること）

- 技術スタックが決まったら、PR ごとのプレビューデプロイと `main` の固定 URL を最初に用意する（最初の Issue にする）。
- AI は PR を出すたびにプレビュー URL を確認してから人に渡す。
