# 005: 人のフィードバックが返って直るまでを最短にする

- 日付：2026-11-25
- 決めた人：（PR のレビューで決める。提案はいうてぃー）

## 決めたこと

- 体験が変わる PR には、レビューする人がいちばん手軽に試せる方法・試し方・見てほしいことを先頭に書く。PR テンプレートに「試し方」欄を足す。
- 試す方法は作るものの形に合わせる（Web なら PR ごとの URL と `main` の固定 URL、ほかの形ならすぐ入れられるビルドや動画）。どの形でも、ログインや準備なしで体験の中心に入れるようにする。
- 感想はどこに書いてもらってもよく、AI が拾って Issue にする。小さな指摘はその日のうちに直して URL 付きで返す。
- 同じ指摘が2回出たら、テスト・自動チェック・AGENTS.md のルールで再発を防ぐ。
- 作るものの形と技術が決まったら、試してもらうまでの手間が小さくなる仕組みを最初に作る。

## 理由

- 実装は AI が速く進められるので、作品の質を決めるのは「人が触って、感想を返して、直る」を何周できるかになる。
- 前に Unity で作ったときは、試すまでの手間が大きく、触る回数が減った。開くまでの手間をなくせば、すき間時間でも触れる。
- 感想を Issue の形で書くのは人にとって重い。AI が拾えば、人は思ったことを書くだけで済む。

## 検討したほかの案

- すべての PR にスマホで開ける URL を必須にする：企画の段階から Web が有利になり、「体験に必要な形を選ぶ」（004）とぶつかる。
- 決まった日にまとめてレビューする：準備はいらないが、1周が長くなり、直す量が一度に増える。

## 影響（変わること・注意すること）

- 作るものの形と技術が決まったら、試してもらう仕組みを最初に用意する（最初の Issue にする）。
- AI は PR を出すたびに、書いた試し方で実際に試せることを確かめてから人に渡す。
