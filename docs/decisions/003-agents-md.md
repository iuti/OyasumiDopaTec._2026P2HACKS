# 003: AI 向けのルールを AGENTS.md にまとめ、重複作業と質問の基準を決める

- 日付：2026-11-25
- 決めた人：（PR のレビューで決める）

## 決めたこと

- AI 向けのルールの本体を `AGENTS.md` に置き、`CLAUDE.md` はそれを読み込むだけにする。
- AI は Issue に着手する前に自分を担当にし、担当者がいる Issue には手を出さない。順番がある Issue は本文に `Depends on #番号` と書く。
- AI が人に聞くのは「体験が変わる」「取り消せない・お金や外部アカウントが絡む」「要件の矛盾や大きな抜け」のときだけ。それ以外は自分で決めて PR に理由を書く。
- 画面や音など、見たり聞いたりしないと判断できない成果物は、ドライブの「05_レビュー」にドキュメントを作って見てもらう。
- 重複した関数や使われていないコードは、AI が小さい専用の PR で整理する。
- docs は書き換えと削除を前提にする（決定を変えたらそのファイルを書き換える、直ったハマりどころは消す）。

## 理由

- Codex など Claude 以外の AI は `CLAUDE.md` を読まず、`AGENTS.md` を読む。メンバーがどの AI を使っても同じルールで動くようにするため。
- 5人の AI が同時に動くと、同じ Issue を別々に始めてしまう。担当者を先に付ければ、ファイルの担当決めをしなくても重複を防げる。
- 「Issue に書いていない仕様はすべて質問する」だと、細かいことまで人に返ってきて、人の負担と待ち時間が増える。人が持つべき判断（体験・設計）だけを聞くようにした。
- docs が追記だけで増えると、古い情報を AI が読んで間違える。
- マージを人が行うルール（001）は変えない。

## 検討したほかの案

- CLAUDE.md と AGENTS.md に同じ内容を書く：二重管理になり、片方だけ更新されてずれる。
- ファイル単位で担当を決める：AI の動きを縛りすぎる。コンフリクトは PR で解消すればよい。

## 影響（変わること・注意すること）

- ドライブの P2HACKS2026 フォルダに「05_レビュー」フォルダを作る必要がある（オーナーの梅さんが作る）。
- 「要相談」ラベルは、AI が人の判断を待っている Issue に付ける。
- 001 の「決定を変えたときは古いファイルを消さない」ルールは、この決定で変わる。
